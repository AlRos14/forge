# PR11 V118 foreign-key and update-fence inventory

This matrix was generated by applying the repository migrations through V120 to an in-memory SQLite database, then enumerating every table with a `pr11_retired_update_*` trigger and every `PRAGMA foreign_key_list` row for those tables.

- Protected tables: **59** (each has a PR11 insert fence and update fence).
- Foreign-key relationships: **152**; all use `ON UPDATE NO ACTION`.
- `ON DELETE SET NULL`: **36**; these conflict with a blanket `BEFORE UPDATE` fence and receive only the exact V119 FK-null exception.
- `ON DELETE CASCADE`: **69**; `ON DELETE RESTRICT`: **42**; `ON DELETE NO ACTION`: **5**. These preserve their existing delete semantics and do not require child UPDATE permission.

## Fence and teardown rules

- **A — semantic mutation:** every protected field other than the listed `SET NULL` columns remains immutable. Inserts remain fenced. A mixed FK-null plus semantic UPDATE fails.
- **B — mechanical FK maintenance:** V119 permits only an old non-null FK value becoming NULL after the referenced parent row is absent. Every other column must compare `IS`-identical, and at least one approved FK column must change. The trigger does not consult `project_deletion_guard`.
- **C — historical delete behavior:** `CASCADE`, `RESTRICT`, and `NO ACTION` retain their schema behavior when reached. The V2 Project deletion path explicitly removes guarded immutable leaves in dependency order and then relies on existing cascades/constraints.
- **D — unreachable parent teardown:** where no V2 hard-delete operation exists, ordinary V2 code cannot reach that parent-delete path. The existing FK action remains defined, and V119 still permits only its exact mechanical NULL if the parent is absent; no new parent delete operation is introduced.

Operation key: `P` = ProjectRepo transactional delete; `T` = physical Task cascade only (the REST Task DELETE is soft); `E` = Execution removal through Task cascade (no direct hard-delete route); `U` = existing admin user deletion; `H` = existing account/Project Chat teardown; `M` = Shared Media or Task media tombstone/soft-delete lifecycle; `N` = no supported V2 hard-delete path for the parent.

For `SET NULL` rows, a `N` parent operation means the exception is not reached by supported V2 teardown today; the database predicate is still limited to the exact dangling FK cleanup. For all other actions, `C` records the unchanged schema behavior.
