## Objective and scope

Plan PR15 is the final migration plan for reference scenarios, reliability, final acceptance, and documentation correction. It verifies the existing Actor, Role, Execution, WorkUnit, Workspace, HarnessAdapter, collaboration, ValidationRun, Evidence, Gate, and lifecycle contracts. It does not introduce a new architecture, Forge-owned cognition, public capabilities absent from the current contract, or a product rename.

PR14 is merged. Its deterministic, file-backed SQLite regression tests reproduce and repair the WorkUnit operation-finish SQLite 517 failure. The post-repair HTTP walkthrough had not run at PR14 merge; S01 now supplies the bounded real HTTP evidence. Execution completion still does not authorize Task merge. PR15 must not start a final Task merge without exact current Gate and authority checks.

The work is limited to reproducible reference scenarios, demonstrated P0/P1/P2 corrections directly needed by those scenarios, and documentation updates justified by results. Existing passing coverage will be reused. Findings outside this boundary will be recorded for the later Forge V2 audit.

## Evidence levels

| Level | Evidence | Permitted claim |
| --- | --- | --- |
| A | Real local SQLite file, Git/worktrees, Forge API/server where needed, and `shell` effects | Local deterministic system behavior for the exact executed scenario |
| B | Controlled fake daemon/provider, injected failures, and concurrency barriers | Protocol, authority, idempotency, and recovery behavior at the tested boundary; not a real external harness run |
| C | Optional native harness or external provider with authorized credentials | Only the named external provider and exact executed operation |

Core acceptance will not require paid tokens, external credentials, or rented infrastructure. A fake provider result will not be reported as native harness availability.

## Acceptance requirements

- Reproducible behavior for S01–S13 below, with each row backed by existing coverage or a smallest necessary focused addition.
- Exact Actor, Role, WorkUnit, Execution, HarnessSession, WorkspaceLease, commit, Evidence, and Gate identities remain authoritative where their contracts require them.
- Concurrent repository writers remain isolated; integration remains an explicit serialized operation.
- An uncertain external effect is not automatically replayed; recovery does not invent continuity or authority.
- Task lifecycle, Review, ValidationRun, Evidence, Gate evaluation, WorkUnit completion, and integration remain distinct records and decisions.
- REST, MCP, CLI, SSE, and web expose only current supported contracts and preserve authorization boundaries.
- Historical data and migrations V001–V134 remain intact. Do not edit historical migration files; add a forward-only migration only if a demonstrated in-scope defect requires one.
- No unresolved in-scope P0/P1/P2. Record unrelated inherited issues without turning them into PR15 gates.
- Final acceptance report is evidence-based and records NOT RUN/PARTIAL where applicable. The complete CI run is reserved for the final candidate HEAD.
